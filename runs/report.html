Invoice Pipeline Eval

The same 400 dummy supplier invoices went through the LangGraph pipeline once per model, on a simulated at-least-once Kafka topic, with every stage running as its own parallel worker pool and crashes, provider errors and ERP timeouts injected (heavy chaos preset). Ground truth decides every score.

Model trade-off

Business rules catch the extraction errors, so a weaker model does not post wrong money; it sends more clean invoices to people. Cost and review hours are projected to a 60,000-invoice month-end day at 90 seconds per review.

Scaling the extraction pool

All 400 invoices queued at once, like a month-end spike, with more extraction workers each run and a provider limit of 120 requests a minute shared by every worker. Throughput climbs with workers until that shared limit starts holding calls back; after that, more workers only wait at the gateway.
